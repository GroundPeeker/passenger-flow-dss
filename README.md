# СППР для управления пассажиропотоком при массовых мероприятиях

Исследовательский код магистерской «Система поддержки принятия решений для
управления пассажиропотоком при проведении крупномасштабных массовых мероприятий».

Система рекомендует оператору (диспетчеру) управляющие воздействия при разъезде зрителей
со стадиона: закрыть или ограничить вход станции метро, переключить указатель на развилке,
запросить дополнительные поезда. Решение принимает оператор, а люди следуют рекомендациям
лишь частично: долю следования c система заранее не знает. Научное ядро работы — метод
формирования рекомендаций с онлайн-оценкой степени следования c и параметров спроса
(фильтр частиц) и сценарным прогнозирующим управлением с ограничением на вероятность
перегрузки.

## Состояние работы

Выполнены этапы 0–4:

| Этап | Содержание |
|---|---|
| 0 | Каркас репозитория |
| 1 | Модель пешеходной сети и векторизованная модель передачи ячеек (CTM) с фундаментальной диаграммой Вейдмана |
| 2 | Станции метро (турникеты, эскалатор, платформа, поезда), спрос, поведение и степень следования c, наблюдения |
| 3 | Метрики, графики и анимация, синтетическая сеть «стадион» (станции метро A и B, остановка шаттлов C) |
| 4 | Базовые стратегии управления и эксперимент «метрики в зависимости от степени следования c», калибровка модели планирования |

Модули прогнозирующего управления (`control/mpc.py`, `control/scenario_mpc.py`,
`control/oracle.py`), фильтра частиц (`estimation/`), обучения с подкреплением (`learning/`)
и прототип интерфейса оператора (`app/`) пока не реализованы — это следующие этапы.

## Требования

- Python 3.11 или новее;
- менеджер окружения [uv](https://docs.astral.sh/uv/);
- ffmpeg — по желанию, для анимаций в `.mp4` (без него сохраняется только `.gif`).

Проверено на macOS (Apple M2 Pro).

## Установка

```
uv sync
```

Команда создаёт виртуальное окружение `.venv` и ставит зависимости по `uv.lock`.
Проект не устанавливается как пакет: все команды запускаются из корня каталога.

## Запуск

Тесты (216 тестов, разложены по этапам в `tests/stage1/` … `tests/stage4/`):

```
uv run pytest                    # все тесты
uv run pytest tests/stage4 -v    # тесты одного этапа
```

Команды проверки модели:

```
uv run python -m sim.bench                        # быстродействие симулятора на эталонной сети из 50 участков
uv run python -m experiments.check_determinism    # два прогона с одним начальным значением генератора совпадают побитово
```

Эксперименты (результаты сохраняются в `experiments/results/`; в архиве они уже есть):

```
uv run python -m experiments.stage3_scenario          # этап 3: 20 эпизодов без управления
uv run python -m experiments.calibrate_model          # калибровка модели планирования (~2,5 мин)
uv run python -m experiments.stage4_compliance plan   # этап 4: подбор фиксированных схем (~3 мин)
uv run python -m experiments.stage4_compliance run    # этап 4: оценочные прогоны (~9 мин)
uv run python -m experiments.stage4_animation         # этап 4: эпизоды для анимации
uv run python -m experiments.stage4_scheme_analysis   # этап 4: анализ выбора фиксированных схем
```

Время указано для Apple M2 Pro.

Рисунки строятся из сохранённых результатов экспериментов:

```
uv run python -m analysis.make_figures --stage 4      # рисунки одного этапа
uv run python -m analysis.make_figures --all          # все рисунки
uv run python -m analysis.make_figures --name <имя>   # один рисунок
```

Рисунки сохраняются в `analysis/figures/stage<N>/`: `.png` (300 dpi), `.pdf` (вектор),
`.csv` (данные рисунка) и `.json` (конфигурация, начальное значение генератора, дата).

## Структура

```
sim/            модель: сеть (network), ядро CTM (ctm), станции (station), спрос (demand),
                поведение (behavior), наблюдения (observation), сборка сценария (simulator),
                метрики (metrics), единицы измерения (units), бенчмарк (bench)
control/        стратегии управления; реализованы базовые стратегии (baselines)
estimation/     оценка состояния (фильтр частиц) — следующие этапы
learning/       обучение с подкреплением и нейросетевой суррогат — следующие этапы
networks/       описания сетей: тестовая развилка (toy_fork.yaml), сеть «стадион» (stadium.yaml)
configs/        параметры модели, сценариев и экспериментов с указанием источников
experiments/    скрипты экспериментов; результаты — experiments/results/
analysis/       построение рисунков (make_figures.py), единый стиль (style.py)
app/            прототип интерфейса оператора — следующие этапы
tests/          автоматические тесты по этапам
docs/           PROGRESS.md, DECISIONS.md, JOURNAL.md, сводка для отчёта по практике
```

Все параметры модели задаются в YAML-файлах `configs/` и `networks/`. Единицы измерения
указаны в именах ключей (например `length_m`, `capacity_ped_per_min`), источник значения —
в комментарии рядом. Все случайные величины порождаются генератором с явно заданным
начальным значением, поэтому результаты воспроизводимы.
